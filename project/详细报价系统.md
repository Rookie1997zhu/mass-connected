# 9. 详细报价系统需求

## 9.1 模块概述

详细报价系统是 MASS CONNECTED 平台从“客户初步询价”进入“正式项目推进”的核心模块。

简单报价主要用于快速估算，而详细报价则用于正式确认项目成本、供应商报价、开发方案、模具方案、生产方案、交期、付款条件、合同内容及后续项目执行。

详细报价系统需要支持：

* 客户提交完整项目资料
* 平台管理员审核需求
* 工程师或 Manager 参与判断
* 供应商参与报价
* 多供应商报价比较
* 自动生成详细报价书
* 客户确认报价
* 转入合同与付款流程
* 转入项目进度管理

---

## 9.2 详细报价系统定位

详细报价系统的定位是：

> 将客户需求转化为可执行的正式制造项目。

详细报价不是简单的价格计算，而是一个完整的业务流程，包括技术确认、供应商确认、报价确认、风险确认和交付条件确认。

详细报价适用于：

* 准备进入量产的项目
* 需要正式模具报价的项目
* 需要产品开发的项目
* 需要 PCB / SMT / 软件 / IC 等开发的项目
* 需要多个供应商比较报价的项目
* 需要平台人工或工程师参与判断的项目
* 需要合同、付款、项目进度管理的项目

---

## 9.3 简单报价与详细报价的衔接

### 9.3.1 从简单报价进入详细报价

用户在简单报价页面生成初步报价后，可以点击：

```text
进入详细报价
```

系统需要自动执行以下动作：

1. 创建一个新的详细报价项目
2. 复制简单报价中的用户信息
3. 复制简单报价中的产品信息
4. 复制已上传文件
5. 复制初步报价结果
6. 将简单报价状态改为“已转详细报价”
7. 通知管理员
8. 引导用户补充更多资料

---

### 9.3.2 直接进入详细报价

用户也可以不经过简单报价，直接从分类进入详细报价。

适用场景：

* 客户已经有明确项目
* 客户已有图纸或BOM
* 客户需要正式量产报价
* 客户需要平台协助开发
* 客户需要一站式产品开发服务

---

## 9.4 详细报价分类

根据 PPT 中分类结构，详细报价包含以下业务：

1. 一站式产品开发
2. PCB开发报价
3. 软件 / IT 服务开发报价
4. 产品设计（准备中）
5. 机构设计（准备中）
6. 注塑模具报价
7. 3D打印报价
8. 硅胶产品报价
9. PVC产品报价
10. 铝挤型报价
11. 塑料挤出报价

后续可继续扩展：

* CNC加工详细报价
* 喷涂加工详细报价
* 环境测试报价
* Abnormal测试报价
* KC认证对应

* 包装设计
* IN BOX / OUT BOX设计
* 量产制造报价

## 9.5 详细报价通用流程

详细报价通用流程如下：

```text
用户登录
↓
进入详细报价分类
↓
选择详细报价类型
↓
填写项目基本信息
↓
上传项目资料
↓
提交详细报价申请
↓
系统生成详细报价项目编号
↓
管理员审核资料完整性
↓
如资料不足，要求客户补充资料
↓
如资料完整，进入内部评估
↓
平台 / 工程师 / Manager 判断可行性
↓
分配给供应商或合作工厂
↓
供应商登录并填写报价
↓
系统汇总供应商报价
↓
平台生成比较报价书
↓
管理员确认最终报价
↓
客户查看详细报价
↓
客户确认或提出修改
↓
确认后生成合同
↓
客户付款
↓
项目转入正式执行阶段
```

## 9.6 详细报价项目状态

详细报价项目需要有完整状态管理。

| 状态     | 说明               |
| ------ | ---------------- |
| 草稿     | 用户正在填写，还未提交      |
| 已提交    | 用户已提交详细报价申请      |
| 等待资料补充 | 管理员认为资料不足，需要客户补充 |
| 资料审核中  | 管理员正在审核资料完整性     |
| 内部评估中  | 平台内部进行技术和成本评估    |
| 供应商报价中 | 已分配给供应商，等待供应商报价  |
| 报价汇总中  | 系统正在汇总多个供应商报价    |
| 平台审核中  | 管理员审核供应商报价和最终价格  |
| 报价已完成  | 详细报价书已生成         |
| 客户确认中  | 等待客户确认报价         |
| 客户要求修改 | 客户对报价或条件提出修改     |
| 已确认    | 客户接受报价           |
| 合同生成中  | 系统正在生成合同         |
| 等待付款   | 等待客户支付定金或费用      |
| 已付款    | 客户已付款            |
| 已转项目   | 转入项目执行流程         |
| 已取消    | 客户或平台取消          |
| 已过期    | 报价超过有效期          |

## 9.7 详细报价项目编号规则

详细报价需要独立编号。

建议格式：

```text
MC-DQ-YYYYMMDD-0001
```

示例：

```text
MC-DQ-20260703-0001
```

其中：

* MC = MASS CONNECTED
* DQ = Detailed Quotation
* YYYYMMDD = 日期
* 0001 = 当日流水号

若由简单报价转入详细报价，可保留关联关系：

```text
简单报价编号：MC-QT-20260703-0001
详细报价编号：MC-DQ-20260703-0001
```

* 所有下载记录应被记录

---

## 9.10 管理员审核流程

用户提交详细报价后，管理员需要先审核资料完整性。

### 9.10.1 审核内容

管理员需要检查：

* 客户信息是否完整
* 项目描述是否清楚
* 文件是否能打开
* 图纸是否足够报价
* 数量是否明确
* 材料是否明确
* 是否需要开发
* 是否需要供应商报价
* 是否存在明显不可行问题
* 是否需要转人工沟通

---

### 9.10.2 审核结果

管理员可以选择：

1. 资料通过，进入内部评估
2. 资料不足，要求客户补充
3. 项目不适合平台处理，拒绝报价
4. 需要人工沟通，转 Kakao Channel
5. 需要 Manager 参与判断

---

### 9.10.3 资料补充

如果资料不足，管理员可以向客户发送补充要求。

补充要求应包括：

* 缺少的资料
* 为什么需要该资料
* 建议上传格式
* 截止时间
* 联系方式

客户补充后，项目状态返回“资料审核中”。

---

## 9.11 内部评估流程

资料审核通过后，进入内部评估。

内部评估主要由平台管理员、工程师或 Manager 完成。

### 9.11.1 评估内容

需要评估：

* 项目是否可执行
* 是否需要开发
* 是否需要模具
* 是否需要多供应商协作
* 是否需要特殊材料
* 是否存在认证风险
* 是否存在品质风险
* 是否存在交期风险
* 是否需要客户调整方案
* 是否适合自动报价
* 是否需要人工报价

---

### 9.11.2 内部评估输出

内部评估后需要输出：

* 推荐执行方案
* 推荐报价方向
* 是否分配供应商
* 是否需要 Manager
* 是否需要工程师 Flow
* 是否需要额外服务费
* 是否建议进入正式项目

---

## 9.12 供应商参与报价

PPT 中明确提到：

> 供应商可以直接参与报价书 작성。

因此，详细报价系统需要支持供应商账号和供应商报价功能。

---

### 9.12.1 供应商账号

平台可以向供应商提供：

* ID
* 密码
* 供应商名称
* 联系人
* 联系方式
* 可报价类别
* 权限范围

---

### 9.12.2 供应商可见内容

供应商登录后，可以查看被分配给自己的报价项目。

供应商可见：

* 项目编号
* 报价类别
* 产品说明
* 必要图纸
* 数量
* 材料要求
* 工艺要求
* 交期要求
* 平台备注

供应商不可见：

* 客户完整联系方式
* 平台利润率
* 其他供应商报价
* 客户与平台的合同金额
* 平台内部备注

---

### 9.12.3 供应商填写报价

供应商需要填写：

| 字段    | 类型 | 说明       |
| ----- | -- | -------- |
| 报价金额  | 数字 | 供应商报价    |
| 单价    | 数字 | 如适用      |
| 模具费   | 数字 | 如适用      |
| 打样费   | 数字 | 如适用      |
| 生产周期  | 数字 | 天数       |
| MOQ   | 数字 | 最小起订量    |
| 付款条件  | 文本 | 如30%定金   |
| 报价有效期 | 日期 | 供应商报价有效期 |
| 备注    | 文本 | 特殊说明     |
| 附件    | 文件 | 报价单或参考资料 |

---

### 9.12.4 供应商报价状态

| 状态   | 说明        |
| ---- | --------- |
| 待报价  | 已分配但未提交   |
| 已查看  | 供应商已查看    |
| 已报价  | 供应商已提交报价  |
| 需要补充 | 平台要求供应商补充 |
| 已修改  | 供应商修改后提交  |
| 已采用  | 平台采用该报价   |
| 未采用  | 平台未采用该报价  |

---

## 9.13 多供应商比较报价

详细报价系统需要支持多个供应商报价后自动汇总。

### 9.13.1 比较维度

系统应支持按以下维度比较：

* 报价金额
* 单价
* 模具费
* 样品费
* 交期
* MOQ
* 付款条件
* 品质能力
* 供应商评分
* 历史合作记录
* 风险备注

---

### 9.13.2 比较报价书

系统应自动生成比较报价书。

比较报价书包含：

* 项目基本信息
* 客户需求摘要
* 供应商报价列表
* 平台推荐方案
* 价格比较表
* 交期比较表
* 风险说明
* 最终建议
* 管理员备注

---

### 9.13.3 对客户显示规则

客户不一定需要看到供应商真实名称。

可采用以下方式：

* 方案 A
* 方案 B
* 方案 C

例如：

| 方案   |    模具费 |   单价 |  交期 | 说明   |
| ---- | -----: | ---: | --: | ---- |
| 方案 A | 10,000 | 1.20 | 25天 | 成本优先 |
| 方案 B | 13,000 | 1.10 | 30天 | 量产优先 |
| 方案 C | 16,000 | 1.50 | 20天 | 交期优先 |

---

## 9.14 平台报价加价规则

PPT 中提到若干加价规则。

### 9.14.1 模具费用加价

规则：

```text
所有模具费用增加 10%。
中国侧 10%，韩国侧 10%。
```

V1.0 需求说明：

* 系统后台应支持设置模具费用加价比例
* 默认可设置为 10%
* 不同国家、不同业务可设置不同加价率
* 最终对客户展示的是加价后的报价

---

### 9.14.2 JIG费用规则

PPT 中提到：

```text
所有 JIG 费用按 2 倍计算。
JIG 通过 Kakao Channel 进行。
```

V1.0 需求说明：

* JIG相关项目应进入人工确认流程
* 系统后台可设置 JIG 倍率
* 默认倍率为 2倍
* 页面提示客户 JIG 费用需人工确认

---

### 9.14.3 工程师 Flow 费用

PPT 中提到：

```text
Engineer Flow 时，需要额外支付 8% incentive。
```

V1.0 需求说明：

* 如果项目需要工程师参与，应增加工程师服务费
* 默认比例：8%
* 管理员可在后台开启 / 关闭
* 管理员可调整比例
* 报价书中应显示为“工程技术服务费”或“工程支持费用”

---

### 9.14.4 样品费用

PPT 中提到：

```text
样品费用也应自动报价。
```

V1.0 需求说明：

* 详细报价中应包含样品费用字段
* 样品费用可自动估算，也可由供应商填写
* 样品费用应在报价书中单独显示
* 样品费用可在正式量产前单独支付

---

### 9.16.2 客户确认页面

| 模具报价    | 7~14天 |
| 电子零部件报价 | 3~7天  |
| 软件开发报价  | 14天   |

PDF中应显示：

```text
本报价有效期为报价日起指定天数内。
```

## 9.28 风险提示

详细报价页面和PDF中应根据项目类型显示风险提示。

### 9.28.1 模具项目风险

* 模具结构可能因产品结构发生变化
* 试模后可能需要修模
* 外观件可能需要额外抛光或表面处理
* 热流道、滑块、镶件等结构会影响价格
* 模具交期受设计确认时间影响

---

### 9.28.2 PCB项目风险

* BOM价格可能变化
* 元件可能缺货
* SMT良率受封装和设计影响
* 功能测试需另行确认
* 认证费用不包含在基础报价中

---

### 9.28.3 软件项目风险

* 需求变更会影响开发周期和费用
* 第三方API政策变化可能影响功能
* 支付系统、登录系统、服务器部署可能需要额外审核
* UI设计和功能开发需分阶段确认

---

### 9.28.4 量产项目风险

* 原材料价格可能变化
* 汇率可能影响最终成本
* 运输费用可能变化
* 品质标准不同会影响生产成本
* 客户确认延迟会影响交期

---

## 9.30 本章结论

详细报价系统是 MASS CONNECTED 从“报价工具”升级为“制造服务平台”的关键模块。

简单报价解决的是客户快速了解价格的问题，而详细报价解决的是客户是否能够真正进入开发、模具、生产和交付的问题。

V1.0 阶段的详细报价系统不需要完全自动化，但必须建立清晰流程：

1. 客户提交完整资料
2. 管理员审核资料
3. 平台进行内部评估
4. 供应商参与报价
5. 系统汇总报价
6. 平台生成详细报价书
7. 客户确认报价
8. 报价转合同
9. 合同转付款
10. 付款后进入项目执行

详细报价系统完成后，平台才真正具备从客户需求到制造执行的闭环能力。
