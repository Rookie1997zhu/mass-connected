# 12. 积分系统与平台运营规则需求

## 12.1 模块概述

积分系统是 MASS CONNECTED 平台的重要运营机制。

平台计划通过积分制度来控制报价功能、资料生成、包装设计、自动文档生成、客户奖励、推广奖励和部分增值服务。

积分系统的核心目的不是单纯做“游戏化”，而是建立一套平台内部的服务计费与用户激励机制。

积分可以用于：

* 查看或生成报价
* 下载 PDF 报价书
* 生成包装刀线
* 使用 AI 自动估价
* 使用部分自动文档服务
* 支付部分平台服务费用
* 奖励用户注册
* 奖励用户评价
* 奖励用户推广平台
* 奖励客户下单

---

## 12.2 积分系统定位

积分系统的定位如下：

> 通过积分机制，将平台中的轻量服务、自动化工具、客户激励和运营推广进行统一管理。

积分系统需要同时满足三个目标：

1. **服务计费**

   * 用户使用自动报价、PDF生成、包装刀线、AI估价等功能时，可以消耗积分。

2. **客户激励**

   * 用户注册、评价、推广、下单时，可以获得积分。

3. **平台留存**

   * 积分可以鼓励用户持续使用平台，而不是一次性询价后离开。

## 12.4 积分基础规则

### 12.4.1 积分是否可当现金使用

PPT 中提到：

> 积分可以像现金一样使用。

因此，积分在平台内可以用于抵扣部分服务费用或购买平台服务。

但需要注意：

* 积分只在 MASS CONNECTED 平台内部使用
* 积分不可直接提现
* 积分不可私下交易
* 积分不可兑换现金
* 积分抵扣范围由平台规定
* 平台保留调整积分规则的权利

---

### 12.4.2 积分兑换比例

PPT 中提到：

```text
10,000韩元 + VAT 10% = 10,000 Point
```

因此，V1.0 可暂定：

|         金额 |           积分 |
| ---------: | -----------: |
| 10,000 KRW | 10,000 Point |

换算关系：

```text
1 KRW = 1 Point
```

是否包含 VAT 需要后续根据韩国税务与支付系统规则确认。

## 12.5 注册赠送积分

PPT 中出现过两个不同版本：

* 注册后提供 10,000 Point
* 注册后提供 100 Point

这两个数字存在冲突。

### 12.5.1 V1.0 建议规则

为了让用户有足够积分体验报价功能，建议采用：

```text
新用户注册成功后，赠送 10,000 Point。
```

原因：

* 如果生成一次报价消耗 1,000 Point，10,000 Point 可让用户体验多次报价
* 有利于提升用户注册转化
* 有利于客户理解平台价值

---

### 12.5.2 后台可配置

由于 PPT 中存在 100 Point 与 10,000 Point 两种写法，系统后台应支持管理员配置注册赠送积分。

后台配置字段：

| 字段                     | 说明        |
| ---------------------- | --------- |
| register_bonus_enabled | 是否启用注册赠送  |
| register_bonus_amount  | 注册赠送积分数量  |
| register_bonus_limit   | 每个用户只赠送一次 |
| register_bonus_note    | 积分说明      |

### 12.7.2 PDF报价书生成

建议规则：

| 功能         |          消耗积分 |

| 生成简单报价 PDF |   1,000 Point |

```text
计算报价 + 生成一次 PDF 合并为一次扣费。
```

```text

```

## 12.8 积分充值

### 12.8.1 充值规则

用户可以通过支付购买积分。

基础规则：

```text
10,000 KRW + VAT 10% = 10,000 Point
```

建议充值档位：

|        支付金额 |          获得积分 |
| ----------: | ------------: |
|  10,000 KRW |  10,000 Point |
|  30,000 KRW |  30,000 Point |
|  50,000 KRW |  50,000 Point |
| 100,000 KRW | 100,000 Point |
|       自定义金额 |          对应积分 |

---

### 12.8.2 VAT处理

PPT 中提到 VAT 10%。

因此充值页面需要明确显示：

* 积分金额
* VAT金额
* 实际支付金额
* 获得积分
* 是否可开发票

示例：

| 项目      |           金额 |
| ------- | -----------: |
| 积分金额    |   10,000 KRW |
| VAT 10% |    1,000 KRW |
| 实际支付    |   11,000 KRW |
| 获得积分    | 10,000 Point |

---

### 12.8.3 充值流程

```text
用户进入 MY PAGE
↓
点击“积分充值”
↓
选择充值金额
↓
确认 VAT 与支付金额
↓
进入支付页面
↓
支付完成
↓
系统确认付款
↓
积分到账
↓
生成充值记录
```

---

### 12.8.4 V1.0 支付确认方式

V1.0 可以先采用人工确认：

1. 用户选择充值金额
2. 系统生成充值订单
3. 用户转账或付款
4. 用户上传付款凭证
5. 管理员确认到账
6. 管理员发放积分

V2.0 再接入：

* 韩国支付系统 PG
* 银行入账确认
* 自动积分到账
* 税务发票自动发行

## 12.11 积分退款规则

如果用户消耗积分后，系统未能完成服务，需要支持积分退还。

### 12.11.1 可退款场景

| 场景           | 是否退款          |
| ------------ | ------------- |
| 系统错误导致报价失败   | 可退            |
| PDF生成失败      | 可退            |
| 用户主动取消已生成报价  | 不退            |
| 用户重复操作       | 默认不退          |
| 管理员判定需要补偿    | 可退            |
| 文件无法识别导致无法报价 | 可部分退或不退，规则需明确 |

---

### 12.11.2 退款方式

积分退款应退回用户积分账户，并生成积分明细。

记录内容：

* 原消耗记录
* 退款原因
* 退款积分
* 操作人
* 操作时间

PPT 中未明确积分有效期。

V1.0 建议暂不设置过期，降低用户理解成本。

后续可以根据运营需要设置：

| 积分类型   | 有效期      |
| ------ | -------- |
| 注册赠送积分 | 6个月或12个月 |
| 活动奖励积分 | 3个月或6个月  |
| 充值积分   | 不过期      |
| 下单奖励积分 | 12个月     |

V1.0 推荐：

```text
充值积分不过期，奖励积分是否过期由后台配置。
```

## 12.13 积分冻结

某些场景下积分需要冻结。

例如：

* 用户发起服务但尚未完成
* 系统等待报价结果
* 用户存在异常行为
* 管理员审核中

### 12.13.1 冻结流程

```text
用户发起服务
↓
系统冻结所需积分
↓
服务成功完成
↓
冻结积分正式扣除
```

如服务失败：

```text
服务失败
↓
冻结积分解冻
↓
积分返回可用余额
```

V1.0 可先不做冻结机制，直接扣除积分。
V2.0 再做冻结机制。

## 12.14 积分与报价系统联动

### 12.14.1 简单报价

简单报价生成时消耗积分。

流程：

```text
用户填写报价信息
↓
点击生成报价
↓
系统检查积分余额
↓
积分足够
↓
扣除积分
↓
生成报价结果
↓
生成PDF
↓
保存报价记录
```

---

### 12.14.2 详细报价

详细报价本身不建议消耗积分。

原因：

* 详细报价通常会进入正式交易
* 如果前期收费太多，可能降低客户提交意愿
* 详细报价更适合由平台通过最终订单获得利润

建议：

| 功能       | 是否消耗积分   |
| -------- | -------- |
| 提交详细报价申请 | 免费       |
| 下载详细报价书  | 免费       |
| 生成比较报价书  | 可由平台内部承担 |
| 特殊分析报告   | 可消耗积分    |
| AI辅助分析   | 可消耗积分    |

---

```text
用户进入包装设计工具

填写产品尺寸
↓
填写包装数量
↓
```

V1.0 可先显示尺寸建议。

## 12.17 积分与推广系统

### 12.17.1 推荐码

后续可为每个用户生成推荐码。

推荐码用于：

* 推荐企业注册
* 追踪推广来源
* 发放积分奖励
* 计算推荐佣金

---

### 12.17.2 推荐奖励流程

```text
老用户分享推荐链接
↓
新用户通过链接注册
↓
新用户完成企业认证
↓
系统记录推荐关系
↓
新用户完成正式订单
↓
老用户获得积分奖励
```

---

### 12.17.3 防作弊规则

推荐奖励需要防止刷积分。

规则建议：

* 同一企业只计算一次
* 同一手机号只计算一次
* 同一邮箱只计算一次
* 推荐奖励需管理员审核
* 被推荐用户完成正式订单后才发放高额奖励
* 自我推荐无效

## 12.18 积分与 Manager 制度

PPT 中后续提到 Manager 佣金制度。积分系统可以与 Manager 制度分开，但可共享部分用户数据。

Manager 收益不建议用普通积分结算，应单独作为佣金系统管理。

建议：

| 项目            | 使用系统    |
| ------------- | ------- |
| 用户报价消耗        | 积分系统    |
| 用户注册奖励        | 积分系统    |
| 推荐企业奖励        | 积分或佣金系统 |
| Manager项目辅导费用 | 佣金系统    |
| 推荐客户量产分成      | 佣金系统    |

---

## 12.19 平台运营规则

积分系统需要配合平台运营规则。

### 12.19.1 运营目标

积分运营主要用于：

* 提高注册率
* 提高报价使用率
* 鼓励用户提交项目
* 鼓励用户评价
* 鼓励用户推广平台
* 提高用户复购
* 降低低质量询价
* 避免平台资源被免费滥用

---

### 12.19.2 新用户运营

新用户注册后，平台应引导：

1. 完善企业资料
2. 获得注册积分
3. 体验简单报价
4. 下载报价书
5. 进入详细报价
6. 联系客服

---

### 12.19.3 老用户运营

老用户应重点引导：

* 复购
* 提交新项目
* 推荐企业
* 评价项目
* 查看项目案例
* 使用更多自动工具

---

### 12.19.4 企业客户运营

企业客户可提供：

* 专属积分包
* 批量报价权限
* 项目优先处理
* 专属Manager
* 特殊价格规则

## 12.21 积分异常处理

### 12.21.1 异常类型

| 异常    | 说明           |
| ----- | ------------ |
| 扣分失败  | 用户使用功能但积分未扣除 |
| 重复扣分  | 同一操作被多次扣分    |
| 积分未到账 | 充值或奖励未发放     |
| 恶意刷积分 | 用户利用规则漏洞获取积分 |
| 退款异常  | 退款后积分未恢复     |
| 余额不一致 | 积分明细与余额不一致   |

---

### 12.21.2 异常处理流程

```text
发现积分异常
↓
管理员查看积分明细
↓
确认异常原因
↓
执行调整操作
↓
记录调整原因
↓
通知用户
```

## 12.25 法务与注意事项

积分涉及支付和平台服务费用，因此需要注意：

1. 积分是否属于预付电子支付手段，需要根据韩国法律确认。
2. 积分是否可以抵扣现金，需要在服务条款中明确。
3. 积分是否可以退款，需要制定规则。
4. VAT和税务发票处理需要单独确认。
5. 积分有效期需要在条款中说明。
6. 平台应保留调整积分规则的权利。
7. 积分不可用于违法交易或平台禁止服务。

## 12.27 本章结论

积分系统是 MASS CONNECTED 平台的重要运营工具。

V1.0 阶段不需要把积分系统做得过于复杂，但必须完成以下核心闭环：

1. 用户注册后获得积分
2. 用户可以查看积分余额
3. 用户生成报价时消耗积分
4. 系统记录积分流水
5. 管理员可以调整积分
6. 积分不足时提示用户充值或联系客服

积分系统的重点是让平台的自动化服务具备可控的使用成本，同时让用户愿意注册、体验报价、提交项目，并持续回到平台使用更多制造服务。

后续随着支付系统、推荐系统、Manager制度和自动文档服务上线，积分系统可以逐步扩展为完整的平台运营体系。
