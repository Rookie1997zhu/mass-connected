# 注塑自动报价 · 二期技术方案（上传 STP 自动识别）

> 对齐 [注塑模具自动报价需求.md](注塑模具自动报价需求.md) 第 8 节。一期「手动填参数自动计算」与**二期阶段 A「上传 STP 自动算重量/尺寸」、阶段 B「倒扣→滑块推断」、阶段 C「几何规则材料推荐 + 图纸 OCR」均已上线**。
>
> 状态：**阶段 A/B/C 均已完成**（2026-07）。阶段 C 的材料推荐当前为几何规则兜底 + 图纸 OCR 抽取，历史数据训练模型待后续迭代。

---

## 1. 目标与范围

### 1.1 目标

客户上传 `.stp` / `.step`（3D 几何文件）后，系统尽可能自动得到一期报价公式所需的输入，减少人工填写，最终形态为：

**上传 STP → 自动算重量/尺寸 + 智能推荐材料/滑块 → 客户确认/微调 → 复用一期公式出报价。**

即「半自动 + 推荐 + 人工确认」，而非「上传即出终价、零确认」。

### 1.2 关键技术边界（必须先对齐）

STP 是**纯几何文件**，只描述形状，**不包含**材料、颜色、公差(精密度)等语义信息。因此：

| 参数 | 能否从 STP 自动得到 | 结论 |
|---|---|---|
| 单件重量 / 体积 | ✅ 几何精确计算 | **自动**（阶段 A） |
| 尺寸包围盒 / 特征统计 | ✅ | **自动**（阶段 A） |
| 是否需要滑块 / 滑块数 | ⚠️ 倒扣(undercut)几何分析，辅助级 | **推断 + 人工复核**（阶段 B） |
| 材料 | ❌ 几何不含 | **推荐 + 客户确认**（阶段 C）或客户填 |
| 颜色 / 精密度 | ❌ 几何不含 | **只能客户填**，或依赖额外 2D 图纸/PMI |

> 结论：「AI 自动识别材料」在纯几何输入下不成立，只能做成基于历史数据的**推荐**，或依赖客户额外上传 2D 工程图做 OCR。方案据此把工作拆成三个可独立交付的阶段。

### 1.3 做 / 不做

**做（本方案范围）**
- [x] **阶段 A（已完成）**：STP 上传、几何解析（体积→重量、包围盒尺寸），自动回填一期表单，客户确认后报价。
- [x] **阶段 B（已完成）**：倒扣分析推断"是否需要滑块/滑块数"，作为**建议值 + 置信度**供人工复核。
- [x] **阶段 C（已完成）**：几何规则材料推荐（低置信度兜底）+ 离线 Tesseract 2D 图纸 OCR 抽取材料/精密度/颜色。

**不做（本期明确排除）**
- 不做"上传即自动出终价、无需任何人工确认"的全自动定价。
- 不做通用 CAD 编辑、装配体自动拆件的完整 DFM 系统。
- 阶段 C 的历史数据训练模型在**无足够历史数据前不启动**，当前以几何规则 + OCR 兜底。
- FAMILY 智能判定（需求第 8.3）默认排除，作为独立增强。
- 不做 OCR 训练/云 API；不做 3D 在线预览；识别结果不落库、不持久化原文件。

## 2. 技术选型

### 2.1 几何解析内核

- **首选 `cadquery-ocp`（OpenCASCADE 的 Python 绑定，pip 可装 manylinux wheel）**：可读 STEP(AP203/214/242)，用 `GProp_GProps` 精确算体积/表面积/包围盒。
- 备选 `pythonocc-core`（功能相同，但主要走 conda，Docker 集成更重）。
- 若只需体积且要极简依赖，备选 `trimesh`+`gmsh` 将 STEP 转网格估体积（精度略低，复杂曲面误差大），仅作降级方案。

> Docker 影响：OCC 相关 wheel 约数百 MB，backend 镜像会明显变大，构建时间增加。需评估镜像体积与 CI 时长（见风险表）。

### 2.2 密度表

材料密度落入后台可维护参数（复用现有 `QuoteParam`，`quote_type="injection"`）：
`density_ABS≈1.05`、`density_ABS_Gf≈1.23`、`density_PC≈1.20`、`density_PA66≈1.14`、`density_PP≈0.91`（g/cm³，最终以后台配置为准）。

重量估算：`weight_g = volume_cm3 × density[material]`。注意 STP 单位多为 mm，体积单位换算 mm³→cm³（÷1000）。

### 2.3 执行方式（同步 vs 异步）

项目当前**无 Celery 等任务队列**（已确认），有 Redis。

- **阶段 A 采用同步解析**：限制上传 ≤ 约 30MB、解析设超时（如 20s），常规零件 OCC 解析在秒级，同步可接受，避免过早引入队列复杂度。
- **预留异步升级位**：若后续出现大文件/装配体导致阻塞，再引入轻量队列（基于现有 Redis 的 `rq` 或 `django-rq`），接口改为「提交→轮询/回调」。本方案在接口设计上预留 `parse_status` 以兼容后续异步化。

## 3. 数据结构（阶段 A 实际落地）

阶段 A **未新增数据库字段**（零迁移）：原始 STP **不持久化**，写入临时路径解析后立即删除。

- 解析结果经 `POST /member/simple-quotes/parse-stp` 返回给前端，用于回填 `weight_g` 与展示体积/尺寸。
- 客户确认后，照常 `POST /member/simple-quotes` 提交 `inputs`；报价仍以 `inputs.parts[].weight_g` 为准。
- 可选：后续若需留证，可在 `inputs` 内嵌 `geometry` 快照（当前由前端会话态持有，不落库亦可）。

解析结果结构示例：

```json
{
  "parse_status": "ok",
  "engine": "ocp",
  "volume_cm3": 4.83,
  "bbox_mm": [42.1, 30.5, 12.0],
  "surface_area_cm2": 61.2,
  "undercut": { "draw_direction": "Z+", "undercut_area_ratio": 0.03, "suggested_sliders": 1, "confidence": "low" },
  "material_suggestion": { "material": "ABS", "source": "geometry_rule", "confidence": "low", "reason": "default" },
  "parsed_at": "2026-07-06T10:00:00Z",
  "error": null
}
```

> 阶段 B/C 增量字段 `undercut`、`material_suggestion` 已在同一结构中扩展，均为建议值 + 置信度，无需改表。图纸 OCR 结果由独立接口 `parse-drawing` 返回（见 4.4）。

## 4. 接口设计

遵循 `.cursor/rules` API 契约（统一响应包 `code/message/data/request_id`、资源化命名、错误码 `MODULE_SCENARIO_REASON`、数据按 buyer 边界隔离）。

### 4.1 解析接口（阶段 A）

- `POST /member/simple-quotes/parse-stp`（方法名 `stpParse`）
  - 入参：`multipart/form-data`，字段 `file`（.stp/.step）。
  - 处理：保存临时文件 → 校验扩展名/大小/魔数 → OCC 解析体积与包围盒 → 倒扣分析（阶段 B）、几何规则材料推荐（阶段 C）→ 返回 `parsed_geometry` 结构（含 `undercut`、`material_suggestion`）。
  - 成功：`data.geometry` = `parsed_geometry`（含建议材料/重量/滑块），`data.densities` = 当前生效密度表，前端据此回填表单。
  - 错误码：
    - `STP_FILE_INVALID`（非 STP/超大/损坏，400）
    - `STP_PARSE_FAILED`（解析内核异常，400，附回退提示"请手动填写参数"）
    - `STP_PARSE_TIMEOUT`（超时，400）
  - 权限：`IsBuyerRole`，仅本人使用；文件与结果不跨用户返回。

### 4.4 图纸 OCR 接口（阶段 C）

- `POST /member/simple-quotes/parse-drawing`（方法名 `drawingParse`）
  - 入参：`multipart/form-data`，字段 `file`（.pdf/.png/.jpg/.jpeg），上限 15MB。
  - 处理：校验扩展名/大小/魔数 → 临时文件 → 图片直读 / PDF 经 PyMuPDF 光栅化首页 → Tesseract OCR（`eng+kor+chi_sim`）→ 关键字抽取材料/精密度/颜色 → 解析后删除临时文件。
  - 成功：`data.ocr` = `{ material, precision, colors, raw_text_excerpt }`，各字段带置信度，前端作**可编辑建议值**回填并标注"需人工确认"。
  - 错误码：`DRAWING_FILE_INVALID` / `DRAWING_PARSE_FAILED` / `DRAWING_PARSE_TIMEOUT` / `OCR_UNAVAILABLE`（400）。
  - 权限：`IsBuyerRole`；OCR 在独立进程 + 超时保护；不落库、不持久化原文件。

### 4.2 创建报价接口（复用一期）

- 现有 `POST /member/simple-quotes` 不变，前端把回填并经客户确认后的参数照常提交。
- 可选：请求体带 `source_parse_id`/引用，用于把上传的 STP 关联进 `source_file`（也可在解析步骤先落库草稿，创建时补 `source_file`）。

### 4.3 前端

- `frontend/src/views/quote/SimpleQuoteView.vue`：注塑表单增加"上传 STP 自动识别"入口 → 调 `stpParse` → 用返回值回填每个零件的重量/建议滑块、并在材料旁展示"推荐材料（可改）"，附**置信度与"以人工确认为准"提示** → 客户确认后走现有生成报价流程。
- 请求走项目封装请求层（`src/api`），i18n 四语言补齐新文案 key，不硬编码。
- 展示：解析出的体积、尺寸、重量、滑块建议须标注"自动估算，仅供参考"。

2. [x] best-effort：异常/超时不阻断体积解析；随 `geometry.undercut` 一起返回。
3. [x] 前端把滑块数作为**建议默认值**回填 `part.slider_count`，标注"建议值·需人工确认"+ 置信度。
4. [x] 自检：无倒扣标准盒 `suggested_sliders=0`；带侧向倒扣件能检出。

### 阶段 C —— 材料智能推荐 / 图纸 OCR（**已完成**）

1. [x] **几何规则推荐**：`recommend_material_by_geometry` 按壁厚代理（体积/表面积）、尺寸段给低置信度材料建议，作为无历史数据时兜底；随 `geometry.material_suggestion` 返回。

3. [x] 前端上传图纸入口 → `drawingParse` → 材料/精密度/颜色作可编辑建议回填，标注置信度与"需人工确认"；失败/不可用回退手动。
4. 历史「几何特征 → 实际成交材料」训练分类模型替换规则推荐 —— 待数据积累后迭代。

## 6. 风险与缓解

| 风险 | 影响 | 缓解 / 验证 |
|---|---|---|
| OCC 依赖使 backend 镜像显著变大、构建变慢 | 部署/CI 变慢 | 评估镜像体积；必要时拆独立"解析服务"镜像；缓存构建层 |
| STEP 版本/导出差异导致解析失败 | 部分文件算不出 | 捕获异常回退手动填写；记录失败样本；OCC 对 AP203/214/242 支持较好 |
| 同步解析大文件阻塞请求 | 超时、并发下降 | 限制文件大小与解析超时；预留基于 Redis 的 `rq` 异步升级位 |
| 重量精度依赖密度取值 | 报价偏差 | 密度后台可调；展示"自动估算"并允许客户覆盖 |
| 滑块/倒扣判定误差（阶段 B） | 误报/漏报影响价格 | 定位为**建议值 + 人工复核**，不直接定终价；建立准确度基线 |
| 材料"识别"预期过高（阶段 C） | 与客户期望不符 | 明确定位为**推荐**，UI 强提示可改；无数据前用规则兜底 |
| 上传文件安全（恶意/超大） | 存储与安全风险 | 校验扩展名+魔数+大小上限；解析在受限环境；文件按 buyer 隔离存取 |
| 迁移新增字段 | 兼容一期数据 | 新增字段可空、默认值兼容；一期手动流程完全不受影响 |
