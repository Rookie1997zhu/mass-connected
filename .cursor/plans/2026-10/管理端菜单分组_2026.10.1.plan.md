# 管理端菜单分组

侧栏现在把约 32 个入口平铺在 [admin/src/layouts/AdminLayout.vue](admin/src/layouts/AdminLayout.vue)。只改菜单呈现，不合并页面，不改路由，不改接口。

## 目标与范围

做：

- 用 Element Plus 的 `el-sub-menu` 收成 6 组。组名写入 [admin/src/i18n/locales/zh.js](admin/src/i18n/locales/zh.js)、[en.js](admin/src/i18n/locales/en.js)、[ko.js](admin/src/i18n/locales/ko.js) 的 `nav.groups.*`。管理端没有日语。
- 分组与现有入口：
  - 日常处理（默认展开）：仪表盘、询价单、询盘、项目、合同、付款、生产订单、聊天纠纷。
  - 客户与供应：会员、工厂、供应商。
  - 报价配置（默认收起）：工艺分类、报价参数、3D 打印报价、报价表格、刀版模板、积分。
  - 商城：商品分类、商品、订单。
  - 官网内容：案例、资讯、博客（文章 / 分类 / 评论仍是下一级）、FAQ、下载资源、页面、网站导航。
  - 系统：管理员。仅 `auth.user.role === 'super_admin'` 时显示。后台创建管理员本来就只允许超级管理员。
- 当前路由高亮改为绑定 `route.path`，不要再写死 `default-active="/"`。侧栏保持现有深色，宽度仍约 220px，菜单可滚动。
- 按现有方式重建管理端镜像：`docker compose up -d --build admin`。

不做：

- 不合并报价参数、3D 打印、报价表格或刀版页面。
- 不按运营 / 销售大面积隐藏菜单。除「管理员」外，三种后台角色仍能看到并打开全部入口。
- 不改仪表盘卡片，不改各业务页表格和表单。

## 实现步骤

1. 在三种语言的 `nav` 下增加组名：`daily`、`partners`、`quote`、`shop`、`content`、`system`。中文分别为日常处理、客户与供应、报价配置、商城、官网内容、系统。
2. 重写 [AdminLayout.vue](admin/src/layouts/AdminLayout.vue) 里 `el-menu` 的子项，按上面的组挂上现有 `index` 路径。博客继续用现在的三个子项。`default-openeds` 只包含「日常处理」。
3. 「管理员」菜单用 `v-if` 判断 `auth.user?.role === 'super_admin'`。
4. 构建并重建 admin 镜像。用超级管理员看分组和当前页高亮；用非超级管理员确认看不到「管理员」，其余组仍在。

## 风险与缓解

- 嵌套博客子菜单在深色侧栏里缩进看不清：只加现有菜单的缩进，不改配色体系。
- 220px 侧栏装不下长组名：组名保持短词，子项继续用已有文案。
- 非超级管理员仍可通过地址打开 `/admin-users`：这是现有后端限制，本次只藏菜单，不补新的接口拦截。

## 验收标准

1. 侧栏默认只展开「日常处理」，其余组可点开，原来的页面都能从对应组进入。
2. 打开询价、报价配置、博客文章时，对应菜单项处于选中状态。
3. 超级管理员能看到「系统 / 管理员」；运营或销售看不到这一项。
4. 中文、英文、韩文组名都有文案。`npm run build`（admin）与管理端镜像构建成功。

确认后按 `feature-implementation` 实现。
