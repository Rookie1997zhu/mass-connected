# 问题列表可见性与 Gemini 翻译

## 目标与范围

**做**
- 「发布进度」→ 时间线；「上报问题」→ 问题列表；买卖双方均可查看。
- 供应商 / 买家项目详情中，时间线与问题列表放在「项目文件」上方。
- 时间线与问题列表每条内容提供「翻译」按钮；目标语言 = 当前站点语言（`ko`/`zh`/`en`/`ja`）；买卖双方都有。
- 后端用 `google-genai` SDK 调用 `gemini-2.5-flash`；API Key 仅从 `.env` 的 `GEMINI_API_KEY` 读取（对应你提供的密钥，**不写入代码、不提交仓库、不进前端**）。

**不做**
- 不把密钥或 `API KEY.MD` 内容提交进 git。
- 不做批量整页翻译、不做翻译结果落库。
- 不改阶段状态机；不为 Issue 新增 stage 字段。

## 现状依据
- 买家 API 已返回 `issues`（[`ProjectDetailSerializer`](backend/apps/project/serializers.py)），但 [`MyProjectDetailView.vue`](frontend/src/views/mypage/MyProjectDetailView.vue) 未渲染问题列表。
- 供应商页已有时间线/问题列表，但排在页面底部文件区之后；阶段展开区内「项目文件」上传块之前没有这两块。

## 实现步骤

1. **买家端：补问题列表 + 调整顺序**
   - 改 [`MyProjectDetailView.vue`](frontend/src/views/mypage/MyProjectDetailView.vue)：区块顺序为制作流程 → 待办 → **时间线** → **问题列表** → 项目文件。
   - 问题列表展示 `title` / `description` / `severity` / `status`；空态用现有 empty 文案。
   - 时间线继续只展示 `is_customer_visible` 的进度（后端 `customer_only` 已过滤）。

2. **供应商端：时间线/问题列表上移到项目文件上方**
   - 改 [`SupplierProjectDetailView.vue`](frontend/src/views/supplier/SupplierProjectDetailView.vue) 当前阶段展开区顺序：
     发布进度 → 上报问题 → **时间线** → **问题列表** → 项目文件（上传）。
   - 删除页底重复的时间线/问题列表区块，避免双份；页底可保留「按阶段文件归档」列表。
   - 时间线优先展示当前阶段相关更新（有 `stage` 且等于当前阶段）；若无 stage 字段的旧数据仍可展示在列表中。问题仍为项目级全量列表。

3. **后端：Gemini 翻译接口（密钥走环境变量）**
   - `.env` / `.env.example` 增加 `GEMINI_API_KEY=`、`GEMINI_MODEL=gemini-2.5-flash`（实现时把你在 `API KEY.MD` 中的 key 写入本地 `.env`，不改计划文件存密钥）。
   - [`backend/requirements.txt`](backend/requirements.txt) 增加 `google-genai`。
   - 新增服务 [`backend/apps/project/translation.py`](backend/apps/project/translation.py)：用 `google.genai.Client(api_key=...)` + `client.models.generate_content(model=..., contents=..., config=system_instruction)` 做纯文本翻译，只返回译文。
   - 新增接口：`POST /api/member/projects/{id}/translate` 与 `POST /api/supplier/projects/{id}/translate`（或统一鉴权后按项目归属校验）。
     - 请求：`{ "text": "...", "target_lang": "zh"|"ko"|"en"|"ja" }`
     - 成功：`{ code: OK, data: { translated_text } }`
     - 权限：仅项目买家或关联供应商；未配置 key → 稳定错误码如 `TRANSLATE_NOT_CONFIGURED`。
   - 不在响应中回传 API Key；日志不打印原文以外的敏感配置。

4. **前端：翻译按钮（买卖双方）**
   - 时间线每条、问题列表每条（标题+描述可各一键或合并一次请求）旁加「翻译」按钮。
   - 调用封装 API，`target_lang` 取自当前 `vue-i18n` locale。
   - 译文展示在原文下方；loading / 失败提示走 i18n；支持再次点击重新翻译。
   - 四语补齐 `translate` / `translating` / `translateFailed` 等 key。

5. **验证**
   - 供应商上报问题后，买家详情可见问题列表内容。
   - 布局：时间线、问题列表均在项目文件上方。
   - 切换站点语言后点击翻译，译文语言跟随；未配置 key 时前端可读错误提示。
   - `manage.py check`、前端 build；密钥不出现在前端包与 git diff 中。

## 风险与缓解
- **密钥泄露**：只写 `.env`（已 gitignore）；提醒勿提交 `API KEY.MD`；前端永不持有 key。
- **Gemini 配额/超时**：接口设合理 timeout，失败返回业务错误码，不阻断项目主流程。
- **可见性**：买家时间线仍只看 `is_customer_visible`；问题列表当前模型无隐藏字段，默认买家可见（与本次产品确认一致）。

## 验收标准
1. 买家项目详情有「问题列表」，能看到供应商上报的标题与描述。
2. 买家时间线能看到勾选「对客户可见」的进度更新。
3. 供应商阶段展开区顺序为：进度表单 → 问题上报表单 → 时间线 → 问题列表 → 项目文件。
4. 买卖双方时间线/问题列表均可一键翻译到当前网站语言。
5. `GEMINI_API_KEY` 仅服务端环境变量；仓库无明文密钥提交。

## 建议下一步
确认本方案后进入实现；实现前先将 `API KEY.MD` 中的密钥配置到本地 `.env` 的 `GEMINI_API_KEY`。
