# 付款凭证预览与卖家确认

## 目标与范围
- 买家上传凭证并刷新履约数据后，在「付款」Tab 显示预览与下载入口；图片直接复用现有 `FilePreviewModal`，PDF继续沿用已有预览能力，其他格式仅下载。
- 仅该付款单合同关联的卖家可看到凭证并执行确认；其他卖家不可访问该付款单。
- 卖家与管理员均可确认付款，任一方首次确认后复用同一业务流程：付款变为 `confirmed`、合同变为 `signed`、幂等创建项目并发送通知。
- 不改付款模型、不做迁移；不开放付款备注等内部字段给卖家。

## 实现步骤
1. **统一付款确认服务与权限边界**
   - 在 [`backend/apps/payment/services.py`](backend/apps/payment/services.py) 提取事务化确认逻辑，复用现有 [`backend/apps/payment/views.py`](backend/apps/payment/views.py) 的确认、合同签署、项目创建和通知行为。
   - 使用事务与行锁处理管理员/卖家并发确认；项目继续依赖现有 `create_project_from_production_order()` 的幂等保护。
   - 新增卖家确认视图：只允许 `IsSupplierRole`，并按 `payment.contract.supplier=request.user` 校验归属；卖家仅可确认已上传凭证且状态为 `pending_confirm` 的付款单。
   - 现有管理员确认接口保留并改为调用同一服务。

2. **扩展卖家付款契约**
   - 在 [`backend/apps/payment/urls.py`](backend/apps/payment/urls.py) 增加 `POST /api/supplier/payments/{id}/confirm`。
   - 在 [`backend/apps/rfq/serializers.py`](backend/apps/rfq/serializers.py) 的 `SupplierPaymentSummarySerializer` 增加凭证预览所需的只读文件信息（URL、文件名、扩展名、是否可预览），继续隐藏 `note` 等内部信息。
   - 买家侧 [`backend/apps/payment/serializers.py`](backend/apps/payment/serializers.py) 保留现有 `proof_url`，补齐同样的文件元信息，避免前端从 URL 猜文件类型。

3. **付款 Tab 增加预览、下载与卖家确认操作**
   - 在 [`frontend/src/api/index.js`](frontend/src/api/index.js) 增加卖家确认付款请求方法。
   - 在 [`frontend/src/components/FulfillmentHub.vue`](frontend/src/components/FulfillmentHub.vue) 中将付款凭证适配为现有 `FilePreviewModal` 的文件结构：买家和卖家均显示「预览凭证 / 下载凭证」。
   - 当角色为卖家、付款状态为 `pending_confirm` 且已有凭证时，显示「确认收款并启动项目」按钮；确认成功后刷新履约数据并发出 `payment-confirmed` 事件。
   - 在 [`frontend/src/views/supplier/QuoteRequestDetailView.vue`](frontend/src/views/supplier/QuoteRequestDetailView.vue) 接收事件并自动切换到「项目」Tab，让卖家立即看到新建项目。

4. **补齐四语文案与回归验证**
   - 在 [`frontend/src/i18n/index.js`](frontend/src/i18n/index.js) 增加凭证预览、下载、确认收款、确认成功及错误文案，覆盖中/英/韩/日。
   - 增加后端接口测试：买家上传后返回凭证信息；关联卖家可见并可确认；非关联卖家 404/403；无凭证或错误状态不可确认；管理员与卖家重复/并发确认不重复创建项目。
   - 执行 `manage.py check`、后端相关测试、前端 build，并分别用买家/卖家账号冒烟验证付款 Tab 与项目跳转。

## 风险与缓解
- **越权查看/确认付款**：卖家查询必须沿 `Payment → Contract → supplier` 过滤，不接受前端传入的供应商标识。
- **管理员和卖家同时确认**：共享事务服务、锁定付款记录，并依赖项目一对一关系与幂等创建，确保只生成一个项目。
- **凭证格式不可预览**：仅图片/PDF显示预览按钮，其他格式保留下载，不阻断确认流程。
- **兼容已有调用方**：保留现有 `proof_url` 和管理员接口，仅增加字段与卖家接口。

## 验收标准
1. 买家上传 JPG/PNG 后无需离开详情页即可点击预览，重新进入页面仍可预览和下载。
2. 关联卖家在同一订单「付款」Tab 可预览/下载该凭证；其他卖家无法通过接口取得凭证信息或确认付款。
3. 卖家在 `pending_confirm` 状态看到确认按钮；点击后付款显示已确认、合同显示已签署，并自动切换至已创建的项目。
4. 管理员仍可按原流程确认；管理员与卖家先后确认不会创建重复项目。
5. 未上传凭证、付款已取消或已确认时，卖家不显示可操作的确认按钮；非法请求返回稳定错误码。
6. 所有新增按钮、提示和状态跟随网站当前语言。
